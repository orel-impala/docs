Impala can run in two places. This is separate from which mode you use — batch runs in both.

## Impala Cloud

We operate the infrastructure, scale GPU capacity, and schedule your requests. You get an endpoint and a credential. Nothing to install.

Pick this to be running today, or when you'd rather not own capacity planning.

## Your Cloud

Impala's data plane is installed into your own AWS account and VPC. Your prompts, inputs and outputs stay inside your account, and traffic reaches the endpoint over AWS PrivateLink rather than the public internet.

Pick this when data residency or network isolation is a requirement, or when you have committed GPU capacity to use.

Setup is a Terraform apply, roughly 30 minutes. See [Install Impala in your VPC (AWS)](/getting-started-infrastructure-setup).

## What differs

| | Impala Cloud | Your Cloud |
| --- | --- | --- |
| Who operates the GPUs | Impala | You, with our data plane on top |
| Where inputs and outputs live | Impala-managed storage | Your S3 buckets |
| Network path | Public endpoint, authenticated | Private, over PrivateLink |
| Setup | None | Terraform, ~30 min |
| AWS quota increases | Not needed | Required first — see [AWS service quotas](/aws_service_quotas_for_Impala_data_plane_deployment) |

## What doesn't

The API. Same endpoints, same request and response shapes, same JSONL format for batch. Code written against one runs against the other with a different base URL.

<Info>
  Batch runs in both. A VPC install is not a prerequisite for trying Impala.
</Info>
