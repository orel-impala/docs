Every request runs in a **completion window**: how soon you need the result back. A wider window gives the scheduler more room to batch and place work, and that room is what you pay less for. The model, its weights and its output are the same in every window.

| Window | Use it for | Returns |
| --- | --- | --- |
| `asap` | Interactive traffic: chat, a user waiting on a response | Real-time |
| `standard` | Agent loops and background work where no one reads tokens as they arrive | Typically within minutes |
| `flex` | Work with no deadline inside the day; lowest cost for async requests | Best effort |
| `batch` | Bulk jobs submitted as a file through the [Batch API](/run-your-first-batch) | Within 24 hours |
